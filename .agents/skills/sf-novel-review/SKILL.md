# SF 소설 독립 검토

## 입력과 검토 범위

1. 프로젝트 루트, 최신 `input.md`, 브리프, 대상 파일의 정확한 버전, 관련 정본·플롯·장면 카드를 읽는다. 작성자의 통과 선언 대신 실제 원고와 요구사항을 대조한다.
2. 과학·연속성, 서사·문장, 또는 전체 검토 중 배정된 범위를 확인한다. 같은 원고에 대한 별도 검토는 동일 버전을 사용하고 메인이 결과를 합친다. 검토 도중 원고가 바뀌면 옛 버전의 통과를 새 버전에 적용하지 않는다.
3. 정본·원고·공용 장부를 수정하지 않는다. 패킷에 지정된 검토 출력 경로와 역할 권한이 모두 쓰기를 허용할 때만 보고서를 파일로 쓴다. 읽기 전용 역할이면 보고서 내용을 메인에 반환하여 저장을 맡긴다. 다른 작업자의 변경을 보존하고 하위 에이전트를 생성하지 않는다.
4. 작성자가 표시한 `사용자 확정 / 작업 가정 / 제안 / 미정`을 유지한다. 브리프가 정하지 않은 문체·소재·길이를 취향으로 강제하지 않는다. 근거가 없거나 필수 입력이 없으면 제한과 영향을 적고 독립적으로 가능한 검토를 계속한다.

## 점검 순서

1. **요구와 인과:** 요청된 장면 목적·범위·분량·계산법, 원인과 결과, 인물의 목표·장애·선택·대가·변화를 확인한다. 편의적 우연, 동기 없는 선택, 준비 없는 해결, 누락된 연결, 회수 기한이 지난 복선을 찾는다.
2. **SF 전제:** 설정의 새로움이 인물 선택과 갈등에 영향을 주는지 확인한다. 기술의 가능 범위·한계·비용·예외를 사건에 적용하고, 기존 규칙을 우회한 해결인지 살핀다. 허용된 창작 가정을 현실 과학과 다르다는 이유만으로 결함 처리하지 않는다.
3. **과학 근거:** 사실·외삽·창작 가정을 나눈다. 최신·전문·불확실한 사실은 실제 검색하고 논문·공식 기관 등 일차 자료를 우선 확인한다. 주장, 출처 URL·제목, 확인 날짜, 적용 조건, 불확실성을 기록한다. 수치·단위·시간 척도·인과 제약을 확인하고 관측 사실과 추론을 분리한다. 접근 실패나 조사 생략은 `미검증`이며 출처를 만들어 채우지 않는다.
4. **연속성과 시점:** 사건 순서·경과 시간·이동 가능성·위치·나이·관계·소지품·부상·지식 획득 시점·명칭을 정본 및 앞뒤 장면과 대조한다. 인물이 알고 있는 것과 전체 진실, 독자가 아는 것을 분리하고 시점 밖 정보 유출을 찾는다. 의도된 비신뢰 서술·반전은 근거와 단서 배치를 확인한다.
5. **독자 경험과 문장:** 정보 공개의 순서, 설명량, 장면 속도, 대사의 목적·인물별 차이, 감정의 준비, 반복·모호한 지시어·문장 연결·시제·호칭을 살핀다. 문체 선호는 별도 제안으로 분리하고, 사용자 문체를 일률적으로 평준화하지 않는다.

## 결함 판정과 보고

보고서를 만들 때 [검토 보고서](assets/review-report.md)를 사용한다. 결함마다 ID, 심각도, 파일·버전·장면 ID·행 또는 짧은 인용, 충돌하는 근거, 영향, 최소 수정안을 기록한다. 행 번호가 없으면 검색 가능한 짧은 인용과 장면 ID로 위치를 식별한다. 사실 확인 전의 의문을 확정 모순으로 적지 않는다.

| 구분 | 판단 기준 |
| --- | --- |
| blocker | 확정된 핵심 조건·정본과 충돌하여 해당 장면의 성립이나 다음 단계 사용을 막음. 또는 필수 검증의 근거가 없어 통과 판단이 불가능함. |
| major | 중요한 인과·동기·정보 공개·연속성 결함으로 독자가 사건이나 선택을 잘못 이해하거나 핵심 효과가 무너짐. |
| minor | 국소 표현·명칭·표기·전환의 문제이며 큰 구조를 바꾸지 않고 수정 가능함. |
| 취향 제안 | 확정 조건을 어기지 않는 대안. 결함 수와 필수 수정 목록에 넣지 않음. |

의도된 모순·미스터리 가능성이 있으면 근거를 먼저 살핀다. 정본의 충돌을 해소해야 한다면 어느 대안을 택하든 영향을 받을 장면을 밝히고 메인 판단을 요청한다. 검토자가 임의로 정본을 확정하지 않는다.

## 재검토와 완료

1. 보고서의 원고 판정은 `pass / revise / blocked`로 표시한다. `pass`는 배정된 범위에서 필수 조건을 충족한 경우, `revise`는 수정 가능한 결함이 남은 경우, `blocked`는 필수 입력·근거 부족으로 판단할 수 없는 경우다. 검토하지 않은 범위는 따로 적는다.
2. 수정본이 오면 새 버전과 이전 검토 ID를 읽고 결함별 `해결 / 잔존 / 사용자 명시 의도 / 검증 불가`를 기록한다. 수정 부위뿐 아니라 영향을 받는 전후 연결과 새 모순을 확인한다. 지적을 삭제하는 대신 처리 근거를 남긴다.
3. 수정 반복은 최대 2회다. 필수 모순은 해결하거나 사용자 명시 의도로 남겨야 원고가 통과한다. 한도 뒤에는 남은 문제·원인·결정이 필요한 선택지를 메인에 반환한다. 일시적 도구 오류는 원인 확인 후 1회 추가 시도한다.
4. 결과는 `run_id`, `task_id`, `status`, `summary`, `artifacts`, `checks`, `issues`로 반환한다. 검토 작업의 `completed`는 보고 완료를 뜻하며 원고 `pass`와 다르다. 요청된 검토를 수행하고 결함을 보고했다면 작업은 완료할 수 있다. 원고 결함은 `issues`와 원고 판정에 남기고, 검토 수행의 완료 기준을 충족했는지는 별도로 확인한다. 필수 검토 자체가 불가능하면 작업을 `blocked`로 반환한다. 검사는 실제 `passed / failed / not_run`과 근거를 포함하며 실패·미실행인 필수 검토를 완료로 표시하지 않는다.
5. 중요한 발견·차단·인계는 [통신·결과 가이드](../harness/references/runtime-guide.md#적극적인-협업과-통신-기록)를 따른다. 읽기 전용 역할은 메인에 메시지와 기록 요청을 반환한다. 메인이 결과 등록·정본 통합·세션 상태 기록을 수행하며 검토 완료를 에이전트 중단이나 사용자 승인으로 해석하지 않는다.
