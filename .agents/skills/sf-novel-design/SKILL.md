# SF 소설 설계

SF 전제(novum)가 세계의 제약을 만들고, 그 제약이 인물의 선택과 대가를 거쳐 사건을 일으키도록 설계한다. 요청한 범위에 필요한 설정만 늘린다.

## 입력과 소유권

1. 현재 요청, 최신 작업 `input.md`, `novel/brief.md`, 관련 정본과 승인된 선행 산출물을 읽는다. 작업 패킷이 없으면 메인이 이번 범위·쓰기 경로·완료 기준을 먼저 정한다.
2. 소재, 분량, 독자, 문체, 과학 엄밀도, 시점 중 제공된 값만 채택한다. 비어 있다는 이유로 하위 장르·막 수·장 수·결말을 확정하지 않는다.
3. 결과를 좌우하는 필수 입력만 질문하고 독립적으로 가능한 설계는 계속한다. 발상 요청에 소재가 없으면 후보를 제안할 수 있다. 선택하지 않은 후보는 정본으로 승격하지 않는다. 선택사항은 `작업 가정` 또는 `미정`으로 표시한다.
4. 워커는 패킷의 배타적 경로에만 쓴다. 기본 산출물 위치는 메인이 지정하는 `.harness/runs/<run-id>/task-<id>/outputs/`다. 메인만 `novel/canon/`, 통합 플롯과 원고를 수정한다. 다른 작업자의 변경을 되돌리거나 승인된 이전 버전을 덮어쓰지 않는다.
5. 설계할 범위와 산출물 단위를 명시한다. 원고 분량이 주어졌다면 공백 포함/제외 글자 수 등 산정 기준도 기록한다. 설계 문서의 길이를 원고 분량으로 취급하지 않는다.

## 기록 원칙

- 각 주장·결정에 `사용자 확정 / 작업 가정 / 제안 / 미정` 중 하나와 근거를 붙인다. 사용자 확정에는 실제 사용자 지시의 출처가 있어야 한다. 메인이 채택한 작업 가정도 사용자 확정으로 바꾸지 않는다.
- 과학적 성격은 별도 축인 `사실 / 외삽 / 창작 가정`으로 적는다. 사실은 출처가 뒷받침하는 범위까지만, 외삽은 출처와 달라지는 가정까지 기록한다. 창작 가정도 작품 내부 한계와 비용은 지켜야 한다.
- 최신 정보, 전문적이거나 불확실한 과학이 설계에 영향을 주면 실제 검색으로 확인한다. 논문·공식 기관 등 일차 자료의 URL, 제목, 발표·갱신일, 확인일, 뒷받침하는 주장, 한계를 남긴다. 검색할 수 없으면 미검증으로 표시하고 필수 설계 판단을 보류한다. 실제 조사하지 않은 내용을 검증했다고 하지 않는다.
- 규칙·인물·사건·장면에는 안정적인 ID를 붙인다. 기존 ID를 유지하고 새 항목에만 새 ID를 준다. 각 항목의 입력 버전, 연결 ID와 미해결 질문을 남긴다.

## 설계 절차

### 1. 구상과 중심 질문

1. 제공된 소재에서 현실과 달라지는 핵심 조건을 한 문장으로 적는다. 발상 단계라면 요청에 맞는 소수 후보와 각 후보의 인간적 갈등을 비교한다.
2. `SF 전제 → 가능한 일과 불가능한 일 → 혜택과 비용의 분배 → 인물의 욕망 → 충돌하는 선택 → 되돌릴 수 없는 대가`를 연결한다.
3. 중심 인물의 목표, 맞서는 힘, 실패하면 잃는 것과 작품이 탐구할 질문을 적는다. 결론이나 교훈을 미리 강요하지 않는다.
4. SF 전제를 제거해도 같은 선택과 결말이 그대로 성립하는지 점검한다. 그렇다면 규칙이 갈등의 원인이나 해결의 대가에 미치는 영향을 보강한다.

### 2. 세계의 규칙과 파급

1. 사용할 핵심 규칙마다 작동 조건, 가능 범위, 금지·한계, 비용, 실패 양상, 예외와 예외의 대가를 적는다. 무제한 능력이나 문제를 즉시 해결하는 새 예외를 숨겨 두지 않는다.
2. 필요한 범위에서 시간·거리·통신·자원·에너지·생명 유지 등 플롯을 제한하는 값을 확인한다. 정밀 수치가 필요 없으면 허용 범위와 판단 근거를 적고 과학적 정밀도를 꾸며내지 않는다.
3. 규칙의 접근권·소유권·통제권을 가진 집단과 비용을 떠안는 집단을 연결한다. 일상, 노동, 권력, 관계 중 사건에 영향을 주는 결과만 확장한다.
4. 규칙의 첫 노출, 재사용, 실패와 해결의 근거가 되는 장면을 연결한다. 독자에게 필요한 규칙은 결정적인 사용 전에 단서로 제시한다. 작중 인물의 오해와 실제 규칙은 분리한다.

### 3. 인물과 대립

1. 인물마다 원하는 것, 잃기 싫은 것, 믿음·오해, 능력·제약, 관계의 긴장과 감출 정보를 적는다. 이 항목들을 고정 성격 목록보다 실제 선택의 이유로 연결한다.
2. SF 규칙이 각 인물에게 주는 혜택과 부담을 다르게 배분한다. 대립하는 인물·집단에도 자기 목표, 자원과 거절할 수 없는 사정을 부여한다.
3. 핵심 선택마다 가능한 대안, 선택한 이유, 즉시 치르는 비용과 뒤늦게 생기는 손실을 적는다. 인물의 변화·유지·퇴행은 이야기의 요청과 결과에 맞게 정하며 성장 서사를 강제하지 않는다.
4. 전체 진실, 인물별 당시 지식, 독자가 아는 정보를 나눈다. 반전은 앞선 행동·단서와 양립해야 한다.

### 4. 인과 플롯과 장면

1. 요청한 단위에 맞춰 사건을 배열한다. 각 사건을 `이전 조건 때문에 → 인물이 선택해서 → 상태가 바뀌고 → 다음 압력이 생긴다`로 연결한다. 단순한 시간순 나열이면 빠진 원인이나 결정을 찾는다.
2. 주요 해결은 이미 제시한 규칙·능력·관계·선택과 비용에서 나오게 한다. 우연이 갈등을 시작할 수 있어도 핵심 해결을 대신하지 않게 점검한다.
3. 장면마다 ID, 시점 인물, 장소/상대 시간, 목표, 장애, 선택, 대가, 변화, 다음 장면 연결을 채운다. 관련 규칙·인물·사건 ID와 당시 지식/전체 진실을 붙인다. [설계 템플릿](assets/design-packet.md)의 필요한 부분만 사용한다.
4. 사건 순서와 독자에게 제시하는 순서가 다르면 별도로 적는다. 이동·통신 지연, 동시 사건, 인물의 위치와 정보 획득 순서를 대조한다. 아직 정하지 않은 구간은 빈 연결을 숨기지 말고 미정으로 남긴다.
5. 범위가 한 장면이면 그 앞뒤 연결까지만, 전체 시놉시스이면 핵심 선택과 결말까지 필요한 수준으로 설계한다. 사용자가 열어 둔 결말은 가능한 경로와 결정 조건으로 남긴다.

### 5. 점검과 인계

1. 승인된 입력과 비교해 규칙 모순, 비용 면제, 인물의 근거 없는 행동, 지식 누출, 인과 단절을 찾는다. 결함은 blocker/major/minor와 위치·근거·영향·최소 수정안을 기록하고 취향 제안은 분리한다.
2. 이번 요청의 필수 항목과 집필 인계 준비 상태를 구분한다. 후보 비교나 일부 세계관 설계는 완성 플롯 없이 완료할 수 있지만, 필수 모순이 남은 구간을 집필 준비 완료로 표시하지 않는다. 사용자가 명시적으로 의도한 예외는 실제 지시 근거와 적용 범위를 기록한다.
3. 수정은 기본 최대 2회, 일시적 도구 오류는 추가 1회까지만 시도한다. 해결하지 못한 필수 문제는 메인에게 반환한다. 범위 확대나 정본 변경은 영향 목록과 함께 제안하며 스스로 확정하지 않는다.
4. 산출물에 입력 버전, 변경 항목, 상태·근거, 영향받는 ID, 열린 질문, 실제 검사와 미실행 항목을 포함한다. 다음 담당자에게 준비된 장면과 의존 조건을 구체적으로 전달한다.
5. 메인이 정본 통합과 후속 작업 배정을 한다. 워커는 하위 에이전트를 생성하거나 공용 실행 장부를 직접 편집하지 않는다. 실행 중 중요한 동료 질문·인계는 [하네스 런타임 가이드](../harness/references/runtime-guide.md)에 따라 기록과 네이티브 전송을 각각 수행한다.

## 부분 재설계

기존 설계를 바꾸면 변경된 전제·규칙·인물부터 읽고 연결된 사건·장면을 추적한다. `유지 / 수정 필요 / 추가 검증 필요`로 영향 범위를 나누고 필요한 구간만 새 버전에 쓴다. 수정하지 않은 항목의 ID와 근거를 유지한다. 이미 작성된 원고에 미치는 영향은 별도 인계하고 과거 산출물을 소급해 수정하지 않는다.

## 템플릿 사용

세계관·인물·플롯을 구조화하거나 설계 결과를 집필에 넘길 때 [설계 패킷 템플릿](assets/design-packet.md)을 읽는다. 요청에 해당하는 절만 복사하고 빈칸 채우기 자체를 목표로 삼지 않는다. 템플릿의 자리표시자는 설정이나 정본이 아니다.
