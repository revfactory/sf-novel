# SF 소설 집필과 퇴고

## 입력과 경계

1. 프로젝트 루트, 최신 `input.md`, 브리프, 해당 장면의 정본·플롯, 직전 장면의 승인된 버전을 읽는다. 수정 작업이면 대상 원고의 정확한 버전과 검토 ID를 함께 확인한다. 상속된 대화만으로 확정 사실을 추측하지 않는다.
2. 작업 패킷의 목표·쓰기 경로·분량·완료 기준을 확인한다. 분량은 대상 범위와 계산법을 함께 정한다. 예: 본문만, 제목·주석 제외, 공백 포함 글자 수, 줄바꿈 제외. 사용자의 계산법이 우선이다. 미정인 전체 소설 분량을 임의로 확정하지 않는다.
3. 원고 대상이나 서로 충돌하는 사용자 지시처럼 진행을 막는 입력만 메인에 확인한다. 선택 가능한 세부사항은 `작업 가정`으로 표시하고 진행한다. 소재가 없는 하네스 구축 단계에서는 예시 원고를 사용자 정본으로 만들지 않는다.
4. `사용자 확정 / 작업 가정 / 제안 / 미정`을 구분한다. 작업 가정과 새로 도입한 사실은 별도 인계 목록에 적는다. 정본 변경이 필요한 수정은 메인에 제안하고 변경이 확정되기 전에는 기존 정본을 기준으로 작성한다.
5. 혼자 작업하지 않음을 전제로 다른 변경을 보존한다. `input.md`가 허용한 경로에만 쓴다. 기본 출력 위치는 `.harness/runs/<run-id>/task-<id>/outputs/`이며 `novel/canon/`, 통합 플롯·원고·리뷰, 공용 장부는 메인이 관리한다. 이미 승인된 산출물은 보존하고 새 버전 경로를 사용한다.

## 장면 초안

1. 장면을 작성할 때 [장면 카드](assets/scene-card.md)를 필요한 수만큼 복사한다. 장면·인물·사건·SF 규칙 ID와 근거 입력을 연결하고 목표 → 장애 → 선택 → 대가 → 변화가 인과적으로 이어지는지 확인한다. 장소·상대 시간·다음 장면 연결을 적는다.
2. 시점 인물이 현재 아는 것, 믿는 것, 독자에게 공개할 것, 전체 진실을 구분한다. 예정된 반전은 단서를 배치하되 시점 인물이 모를 지식을 서술에 섞지 않는다. 현재의 시점·시제·거리·명칭·문체 약속을 유지한다.
3. SF 전제가 장면의 선택이나 대가를 바꾸게 한다. 기술의 작동 범위·한계·비용·예외를 적용하고, 편리한 새 능력으로 갈등을 해소하지 않는다. 설명은 인물의 행동·실패·관찰에 필요한 만큼 배치한다.
4. 장면 전후에 달라지는 상태를 확인하며 본문을 쓴다. 각 인물의 욕망과 제약이 대사·행동에 드러나게 하고, 장면 끝의 변화가 다음 행동을 낳게 한다. 매 장면에 같은 절정·반전을 억지로 넣지 않는다.
5. 사실·외삽·창작 가정을 구분한다. 전문적이거나 최신 검증이 필요한 사실은 실제 자료를 찾아 출처·확인 날짜·적용 범위·불확실성을 남긴다. 조사하지 않은 부분은 `미검증`으로 표시한다. 창작 가정 자체를 과학적으로 입증된 사실로 쓰지 않는다.
6. 연결된 장면과 장은 앞 버전을 읽은 뒤 순서대로 쓴다. 독립 조사나 같은 원고에 대한 서로 다른 검토의 병렬화는 메인이 조정한다. 추가 에이전트를 직접 생성하지 않는다.

## 퇴고와 결함 수정

1. 초안 작성 뒤 인과·인물 선택·시점·시간·과학 규칙을 먼저 점검하고, 다음으로 정보 공개·장면 속도·대사·문장·중복을 다듬는다. 문장 미화로 구조 결함을 덮지 않는다.
2. 독립 검토가 있으면 지적 ID별로 `반영 / 미반영 / 메인 판단 필요`와 근거를 적는다. blocker·major를 우선 고치고 취향 제안은 사용자 문체와 목적에 맞을 때만 채택한다.
3. 최소 범위로 수정하되 원인과 영향을 함께 확인한다. 시간·지식·물품·관계·기술 규칙을 바꿨다면 영향을 받는 이후 장면을 인계에 명시한다. 소유 범위 밖의 장면은 직접 고치지 않는다.
4. 새 버전에서 해당 결함과 그 주변 연결을 다시 확인한다. 원고 파일은 새 버전으로 쓰고 원본과 승인된 산출물을 덮어쓰지 않는다. 같은 검토에 대한 수정은 최대 2회이며, 그 이후의 필수 결함은 숨기지 않고 메인에 남은 원인과 선택지를 반환한다. 일시적 도구 오류는 원인 확인 후 1회 추가 시도한다.

## 확인과 인계

- 본문을 실제로 읽고 장면 카드 대비 충족·누락을 기록한다. 정해진 계산법으로 실제 분량을 측정한다. 계산하지 않았다면 숫자를 추정해 실측이라고 보고하지 않는다.
- 등장인물의 위치·소지품·부상·지식·관계와 사건 순서, SF 기술의 한계·비용을 전후 상태와 대조한다. 자기 점검을 독립 검토 통과라고 부르지 않는다.
- 새 원고, 장면 카드, 인계 메모를 허용된 경로에 작성한다. 인계 메모에는 입력 버전, 작성 범위, 분량과 계산법, 변경·가정·정본 제안, 결함별 처리, 다음 장면에 전달할 상태, 검증과 남은 문제를 넣는다.
- 결과는 `run_id`, `task_id`, `status`, `summary`, `artifacts`, `checks`, `issues`로 반환한다. `status`는 `completed / blocked / failed` 중 하나이며, 검사에는 실제 `passed / failed / not_run`과 근거를 적는다. 미해결 필수 모순은 해소되거나 사용자 명시 의도로 기록되어야 원고를 완료로 인계할 수 있다.
- 중요한 발견·차단·인계는 [통신·결과 가이드](../harness/references/runtime-guide.md#적극적인-협업과-통신-기록)에 따라 기록 후 전달한다. 메인이 결과를 등록하고 정본을 통합한다. 작업 완료는 에이전트 중단이나 사용자 승인과 동일하지 않다.
