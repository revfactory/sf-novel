# SF 소설 집필 총괄

## 목표와 첫 응답

사용자의 구상을 한국어 소설로 발전시키고, 기존 원고의 의도와 목소리를 보존한다. 요청한 범위(구상안, 플롯, 한 장면, 한 장, 전체 원고, 퇴고본)를 마치면 종료한다. 집필 요청을 하네스 구축으로 바꾸거나 미요청 장편을 쓰지 않는다.

1. `AGENTS.md`, `novel/brief.md`, 정본·플롯·현재 원고, 관련 실행 요약을 읽는다. 새 요청과 이전 작업의 후속을 구분한다.
2. 첫 구상이라면 소재·규모·정서 중 결과를 좌우하는 정보만 짧게 묻는다. 아이디어가 없으면 독립적인 전제 3개와 각 주인공·딜레마를 제안한다. 미정과 임시 가정을 명시하고 독립 준비를 계속한다.
3. 사용자가 제시한 사실과 문장을 우선한다. 제목, 시점, 결말, 길이, 하드 SF 여부를 사용자가 정했다고 꾸미지 않는다. 매 단계 승인을 요구하지 않는다. 사용자의 지시로 허용된 수정은 바로 수행한다.
4. 작업 범위와 완료 기준을 먼저 기록한다. 글자 수 목표가 있으면 공백 포함/제외와 허용 편차를 명시한다. 분량이 없으면 제안 또는 임시 작업 단위로 표기한다.

## 경로와 정본

- `novel/brief.md`: 사용자의 목표, 범위, 미정 항목.
- `novel/canon/world.md`: 세계·기술의 규칙, 비용·한계·예외, 사실/외삽/창작 구분.
- `novel/canon/characters.md`: 인물의 욕망·두려움·관계·지식 상태.
- `novel/canon/timeline.md`: 사건 순서·시간·이동·인물별 정보 획득.
- `novel/canon/style.md`: 시점·시제·문체, 사용자의 문장 선호.
- `novel/canon/decisions.md`: 설정 ID, 상태, 근거, 변경 사유와 영향.
- `novel/outline/plot.md`: 인과적 플롯과 장면 카드.
- `novel/manuscript/`: 메인이 통합한 원고 버전. 수정 전 파일을 보존한다.
- `novel/reviews/`: 검토·수정 기록. 작업자 출력과 함께 해당 원고 버전을 명시한다.

정본 상태는 `사용자 확정`, `작업 가정`, `제안`, `미정`으로 구분한다. 작업 가정도 현재 집필의 공통 제약이지만 사용자 확정과 동일시하지 않는다. 미정은 모순이 아니며, 의도적 불확실성·신뢰할 수 없는 화자는 실제 설정 모순과 구분한다.

메인만 공용 정본과 통합본을 편집한다. 워커에게는 실행별 `task-<id>/outputs/`의 배타적 파일을 배정한다. 승인된 인계 출력은 변경하지 않고 수정본을 새 경로에 쓴다. 긴 원고는 관련 장면·정본 ID·요약을 패킷에 담고 실제 판단에 필요한 원문도 읽게 한다.

## 역할과 절차 선택

| 역할 | 책임 | 읽을 스킬 | 기본 쓰기 경계 |
| --- | --- | --- | --- |
| `sf_worldbuilder` | 세계·기술·과학 근거와 인간적 파급 | [설계](../sf-novel-design/SKILL.md) | 배정된 세계관 제안 출력 |
| `sf_plotter` | 인물·갈등·인과 플롯·장면 카드 | [설계](../sf-novel-design/SKILL.md) | 배정된 인물·플롯 제안 출력 |
| `sf_writer` | 장면·장 초안과 피드백 기반 수정 | [집필](../sf-novel-draft/SKILL.md) | 배정된 원고 버전 출력 |
| `sf_editor` | 감정·서사·리듬·문장 검토 | [검토](../sf-novel-review/SKILL.md) | 읽기 전용, 결과는 메시지 |
| `sf_continuity` | 시간·정보·기술·설정 정합성 | [검토](../sf-novel-review/SKILL.md) | 읽기 전용, 결과는 메시지 |

필요한 역할만 호출한다. 짧은 문장 수정은 메인이 수행할 수 있다. 세계관·인물·플롯은 공통 전제 동기화 → 필요한 설계 → 통합 순서로 진행한다. 연속된 장은 앞 장 결과에 의존하므로 순차 집필한다. 독립 조사, 확정 전제 아래의 대안 탐색, 동일 원고에 대한 두 종류 검토는 병렬화할 수 있다. 초기 대안들은 확정 사실로 합치지 않는다.

구상·설계에는 설계 스킬, 초안·퇴고에는 집필 스킬, 독립 리뷰에는 검토 스킬을 해당 역할이 직접 읽게 한다. 과학 사실을 검증할 때에는 실제 조사 근거를 남기고, 창작 전제를 현실의 검증된 사실로 설명하지 않는다.

## 실행 관리

복수 산출물·위임·설정 변경에 따른 재실행에는 [실행 계획](references/run-planning.md)을 먼저 읽는다. 단순 편집에는 불필요한 실행 장부를 만들지 않는다.

1. 메인이 필수 입력과 스킬의 실제 존재·내용을 확인한다. [입력 검사기](scripts/check_inputs.py)를 `python3 .agents/skills/sf-novel-orchestrator/scripts/check_inputs.py --project . --plan PLAN.json`으로 실행하고, 실패하면 해당 작업 배정을 막는다. `run.py ready`는 없는 입력을 자동 거부하지 않으므로 이 검사를 생략하지 않는다. 선택 입력은 inputs에서 제외하고 결정에 사유를 쓴다. 메인이 `run.py init`으로 새 실행을 만든다. 후속 작업은 `resume`으로 이전 실행을 보존한다. 각 작업에 불변 입력, 결정, 스킬, 의존성, 배타적 소유권, 산출물, 검증, 재시도 한도를 지정한다.
2. [네이티브 실행·통신 가이드](../harness/references/runtime-guide.md)를 읽고 실제 역할 목록과 동시 실행 한도를 확인한다. 첫 대기 자식 하나의 실제 ID를 확인한 뒤 준비된 작업에 재사용한다. `run.py start`로 ID를 등록하고 최신 `input.md`를 실제 후속 실행 도구로 전달한다.
3. 이번 런타임의 `collaboration.spawn_agent`, `followup_task`, `send_message`, `list_agents`, `interrupt_agent`는 노출된 경우에만 사용한다. 다른 세션에서는 그 세션의 실제 스키마를 확인한다. 새 TOML 역할이 노출되지 않으면 빌트인 역할에 해당 TOML 지침과 스킬 경로를 명시해 전달하고 대체 실행 사실을 기록한다. 모델과 추론 수준을 고정하지 않는다.
4. 의존성이 준비된 독립 작업만 팬아웃한다. 세계관/플롯 공유 파일, 같은 장, 같은 출력·캐시를 병렬 수정하지 않는다. 자식의 재귀 위임은 기본 금지한다. 메인은 공용 계약과 통합을 진행한다.
5. 중요한 발견·질문·답변·차단·인계는 `communication.py log`로 먼저 기록하고 실제 메시지로 전달한 뒤 전송 결과를 상관 ID로 연결한다. 읽기 전용 역할은 메인이 기록한다. 동료의 실제 ID와 담당 경계를 알려준다. 기록만으로 전송됐다고 하지 않는다.
6. 메인이 결과와 실제 파일·검사 근거를 확인하고 `run.py result`로 등록한다. 실제 유휴·중단 응답을 별도로 확인하여 `run.py agent`로 기록한다. 결과 등록이나 중단 요청만으로 소유권을 다른 작성자에게 넘기지 않는다. `interrupt_agent`를 세션 종료라고 보고하지 않는다.
7. 등록한 산출물은 불변으로 보존한다. 통합은 새 파일로 수행하고 정본 채택은 결정 기록에 남긴다. 검토된 버전과 최종 전달 버전이 같은지 확인한다. 최종 통합 이후 변경이 있다면 관련 검토를 다시 한다.

## 검토, 오류와 부분 재실행

- 원고 검토는 연속성·과학/서사·문장을 분리하고 위치·근거·영향·최소 수정안을 요구한다. 취향은 결함과 구별한다. 리뷰어는 원고를 직접 고치지 않고 작성자가 수정한다.
- 일시적 도구 실패는 원인 확인 후 1회 추가 시도, 검토 후 수정·재검토는 기본 최대 2회다. 한도를 넘긴 필수 실패를 통과 처리하지 않는다.
- 필수 입력 누락은 해당 작업을 blocked로 기록하고 독립 작업만 계속한다. 첫 spawn이 부모 스레드 오류로 ID 없이 실패하면 추가 생성을 중단한다. 메인이 실질 작업을 순차 수행하며 네이티브 미실행 작업은 pending, 검사는 failed/not_run으로 남긴다. 가짜 ID를 만들지 않는다.
- 정본이 바뀌면 그 규칙을 사용한 플롯·장면·리뷰를 추적한다. 입력 내용만 바뀌면 `resume`, 목표·결정·소유권·작업 구성이 바뀌면 개정 계획을 함께 전달한다. 최신 패킷을 다시 읽게 한다. 영향 없는 결과만 재사용한다.
- 구조 검사, 실제 작업 실행, 문학적 검토, 스킬 자동 선택은 별도 근거다. 스킬 파일 존재만으로 자동 호출 성공을 주장하지 않는다.

## 완료

요청 범위·정본·시점·인과관계·분량 기준을 충족하고, 필수 검토에 미해결 실패가 없어야 한다. 장면은 인물의 선택과 변화를 만들며 SF 전제가 갈등과 대가에 영향을 주는지 확인한다. 하네스 실행은 `validate.py --project . --run <run-id> --complete`로 최신성을 확인한다. 명령은 프로젝트 루트에서 `.agents/skills/harness/scripts/`의 실제 파일을 실행한다.

최종 응답은 원고/설계 파일 링크, 완료 범위, 중요한 임시 가정·남은 문제를 간결하게 전달한다. 실행하지 않은 과학 조사나 리뷰를 통과로 보고하지 않는다. 검토 과정과 실행 장부를 소설 본문에 섞지 않는다.
